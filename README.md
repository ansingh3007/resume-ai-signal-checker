A command-line tool that checks a `.docx` (or plain text) resume for the
signals that AI-detector heuristics and ATS plugins actually key on — plus
a check against [Harvard FAS's published resume-writing
guidance](https://careerservices.fas.harvard.edu/resources/create-a-strong-resume/).

No API keys, no uploads to a third party, no sign-up. It runs entirely on
your machine and never sends your resume anywhere.

## Why this exists

There's no hidden "watermark" embedded in AI-generated text — no secret
token you can scan for and strip out. What actually gets a resume flagged
by a recruiter, an ATS plugin, or a basic AI-detector isn't magic, it's a
short list of very ordinary, checkable patterns: leftover document
metadata, stock phrasing, repeated sentence structure, and a handful of
resume-writing rules that generic AI output tends to violate by default.

This tool checks for exactly those things, nothing more, nothing
mysterious.

## What it checks

| # | Check | What it's looking for |
|---|-------|------------------------|
| 1 | **Document metadata** | Leftover tool fingerprints in `docProps/core.xml` / `docProps/app.xml` — things like "Generated by ChatGPT," suspicious app names, or stray `customXml/` parts some AI writing tools inject |
| 2 | **AI-cliché phrasing** | A curated list of stock LLM-isms: *leverage, seamless, spearheaded, cutting-edge, in today's fast-paced environment,* etc. |
| 3 | **Sentence "burstiness"** | Human writing varies sentence length a lot; uniform AI output often doesn't. Flags an unusually low coefficient of variation across sentence lengths |
| 4 | **Repetitive bullet openers** | The same verb opening 3+ bullets — a common sign of formulaic, unedited generation |
| 5 | **Harvard FAS — pronouns** | Harvard's explicit rule: no personal pronouns (*I, We, My, Our*) in resume bullets |
| 6 | **Harvard FAS — action verbs** | Every bullet should open with a verb from [Harvard's action-verb bank](https://careerservices.fas.harvard.edu/resources/create-a-strong-resume/) (Leadership, Communication, Research, Technical, Teaching, Quantitative, Creative, Helping, Organizational) |

## Usage

```bash
# Report findings — read-only, never writes or modifies anything
python3 resume_clean.py inspect resume.docx

# Strip document metadata fingerprints -> writes a NEW file
python3 resume_clean.py clean resume.docx -o resume.cleaned.docx

# Also works on plain text / markdown resumes (metadata checks are skipped)
python3 resume_clean.py inspect resume.txt
```

`inspect` is always safe to run — it opens the file, reads it, prints a
report, and touches nothing. `clean` is the only command that writes
anything, and it only ever touches metadata, never your actual resume text.

## How it works

1. **Opens the `.docx` as a ZIP.** A `.docx` file is a ZIP archive of XML
   files under the hood — no special library needed, just Python's
   built-in `zipfile`.
2. **Reads `docProps/core.xml` and `docProps/app.xml`.** These hold the
   document's author, last-modified-by, and creating application. The
   script checks them against a list of tool-name fingerprints (ChatGPT,
   Claude, Copilot, Jasper, etc.) and flags any hit.
3. **Extracts visible text from `word/document.xml`.** Every `<w:t>` text
   run inside every paragraph is pulled out and joined into plain lines —
   this reconstructs your bullets and headers as text the same way a
   human would read them.
4. **Runs the content checks** described in the table above against that
   extracted text — cliché matching, bullet-opener frequency, sentence
   length variance, pronoun search, and action-verb validation.
5. **Prints a report.** `inspect` never writes anything back to disk.

The separate `clean` command re-opens the same metadata files, blanks out
the fingerprint-y fields (`creator`, `lastModifiedBy`, `Application`,
etc.), strips any `customXml/` parts, and writes the result to a new file
— it never rewrites your resume's actual text.

## Requirements

Python 3.9+ and nothing else. Every module used
(`argparse`, `zipfile`, `re`, `statistics`, `pathlib`,
`xml.etree.ElementTree`) is part of the Python standard library — no
`pip install` needed.

## Limitations

- This is a **heuristic** tool, not a certified AI-detector. It catches
  the same easy tells a careful human reviewer or a basic ATS plugin
  would catch — it does not make a scientific or legal claim about
  whether text is "AI-generated."
- The bullet-opener and Harvard-verb checks are tuned for a
  **"Bold Label: sentence"** bullet style (e.g. *"Led Analytics: Directed
  a team of..."*). If your resume doesn't use bold labels before each
  bullet, these two checks fall back to checking the whole line as-is,
  which may over- or under-flag lines that are really job titles or
  skill-category headers rather than accomplishment bullets.
- Cliché and pronoun matching is simple substring/regex matching, not
  semantic — it won't catch a rephrased cliché, and it won't understand
  context (e.g. "I" inside a quoted testimonial would still be flagged).
